## Audit pass — 2026-11-08

A review of the uncommitted v2.4 code found these defects. All are fixed in source; device behavior still needs the manual checks listed below.

| Area | Defect | Fix |
|---|---|---|
| Android tags | jaudiotagger chooses its reader by file extension, and MediaStore URIs (`…/media/42`) have none. Every MediaStore tag read and write failed, so library BPM/key extraction, embedded lyrics, and tag editing did not work for the default library. | The extension comes from the provider display name or MIME type. Readable MediaStore paths are read in place instead of copied; scan-time copies skip files over 150 MB. |
| Android tags | The editor opened with blank Year, Track and Lyrics and wrote every field, so **saving erased those tags**. Empty TRACK/BPM values also made MP4 saves fail. | The dialog loads the file's current tags first and Save stays disabled until it has. A blank field now removes the tag. The edited temp file is re-parsed before it replaces the original. |
| Android favorites | Legacy SAF favorite IDs were re-applied on every scan, so un-favoriting a migrated SAF track did not stick. Concurrent favorite toggles could lose a write. | Migration runs once per track (recorded in `migrated_saf_ids`) before favorites are read; toggles are serialized. |
| Android SLM stats | Skip detection read the player position after ExoPlayer had moved on, so every manual skip counted as a skip. Tapping a song in a list also recorded a skip for the list's first song, and restoring the paused queue counted as a play. | Stats are tracked for the track that actually started, using the last polled position. |
| Android queue | Removing the playing song from the queue left it shown as current. "Play next" on the playing song interrupted playback. | The queue copy is updated before the player fires its transition; "Play next" ignores the current song. |
| Android resume | Saved position was dropped when the song's duration was unknown (0). | Position is clamped only when a duration is known. |
| Android artwork | `setPlaylist()` re-encoded, hashed and wrote every cached cover on the main thread. | Artwork URIs are cached per song, and covers that are already small JPEGs are not re-encoded. |
| Lyrics (both) | `[offset:]` was applied in the wrong direction. Desktop also dropped empty timestamped lines (instrumental gaps). Android 8–9 never read embedded lyrics for MediaStore songs. | Positive offsets now show lyrics sooner; desktop keeps gap lines; embedded lyrics are read on every API level. |
| M3U (Android) | Export names were cut at the first dot ("Mr. Brightside mix" → "Mr.m3u8"); import names came from the document ID; SAF file names were not percent-decoded; "Artist - Title" entries never matched; imports during library load reported no matches. | Fixed, with new unit tests. |
| Repo hygiene | Eight Kotlin files still began with a UTF-8 BOM (A-25). | Removed. |
| F-Droid | `defaultConfig.applicationId` had been changed to the Play name `com.orbitwork.VoidPlayer`, so F-Droid would reject 2.4.0 and existing installs could not update. The fdroiddata recipe's `gradle: [yes]` also cannot build with the new flavors, and the fastlane changelog was over F-Droid's 500-character limit. | `fdroid`/default keep `com.tushar.voidplayer`; only `full` uses the Play package. The `fdroidRelease` APK is named as the recipe's `Binaries:` URL expects. CI now builds the F-Droid release and checks package, tag and changelog. Remaining steps (tag `V2.4.0`, fdroiddata MR switching to `gradle: [fdroid]`, upload the signed APK) are in [docs/FDROID_RELEASE.md](docs/FDROID_RELEASE.md). |

## SLM v2.1 — 2026-11-08

The Kotlin and C# ports changed together; `test-fixtures/sml-v2.json` (52 cases) is still the shared contract, and both suites pass it.

| Area | Before | Now |
|---|---|---|
| Key parsing | "A minor", "Amaj" and Open Key ("1m", "8d") returned no key; "DM" read as D minor | All of these parse; lowercase `m` = minor, uppercase `M` = major |
| Harmonic score | Every move past an adjacent key scored 0.5, the same as an unknown key | Same 1.0 · adjacent/relative 0.9 · diagonal 0.7 · two steps 0.6 · then −0.15 per step to 0; unknown stays 0.5, so a known clash ranks below missing data |
| Tempo score | A 25 % BPM jump still scored 0.8 | Linear to 0 at a 25 % change, half/double time still 1.0; unknown 0.6 |
| Mood words | Substring match ("sun" hit "Sunday", "night" hit "nightcore") | Whole-word match, with a few more terms ("blues", "party", "lonely", …) |
| Flow score | 0.30 mood + 0.25 energy + 0.20 tempo + 0.25 harmonic | 0.25 mood + 0.20 energy + 0.20 tempo + 0.25 harmonic + 0.10 texture (valence, danceability, acousticness similarity) |
| Radio pick | Random among the top 3 even when #3 scored far lower; no tempo rule; desktop scored only the first 200 songs in the queue | Random only among picks within 0.05 of the best; candidates with an effective (half/double-aware) BPM jump over 25 are dropped when both songs have BPM, with a fallback so radio never stalls; desktop scores the whole queue |

The v2.4 radio acceptance rule (100 picks, no repeat in the last 50, no BPM jump over 25) is now an automated test on both platforms (`SmlRadioTest`, `SmlV2Tests.LongRadioSession_…`). It runs on a synthetic tagged library; a real-library device check is still listed below.

## Windows UI redesign — 2026-11-08

The design is on the "Void Player Windows Redesign" canvas (Library, Now Playing, Graphite tokens). In code:

- `App.xaml` defines graphite tokens (ground, pane, surface, selected, hairline, three text levels, accent, favorite), a type ramp, and accent/secondary/subtle/icon button and segmented styles. It overrides the system accent and the NavigationView and ListView brushes. The old `Void*` keys point at the new tokens.
- Title bar: one brand mark and the version (tagline removed). The navigation pane holds search, with no second logo, and typing from another page jumps to Songs.
- Songs: the page is titled "Songs" with a count and total length; Play all is the single accent action; the All/Favorites pills are a segmented control. The playing row uses an accent title and a play glyph over the artwork instead of a colored left border. Favorites and search with no results get their own message; the empty-library state shows only when the library really is empty.
- Player bar: neutral pane, white play button, format as plain text, inline volume slider in place of the flyout, accessible names on every icon button.
- Now Playing and the other pages: the old green-tinted hexes are remapped to graphite. The glow halo and accent-filled tab pills are gone, and the tabs are a segmented control. The album accent is lightened until it reaches 4.5:1 on the ground (`Services/AccentContrast.cs`).
- Not yet checked in a running window: hover/pressed states, the NavigationView brush overrides, and very long titles. Needs an interactive desktop session.

## Android Graphite theme and theme switch — 2026-11-08

Design: the "Void Player Android Graphite" canvas (Library, Now Playing, full-length Settings with a working theme switch).

- `ui/theme/Theme.kt` has two palettes, `GraphitePalette` (same tokens as Windows) and `ClassicPalette` (the exact 2.3 colors). `VoidTheme.mode` is Compose state, and the shared names every screen already uses (`SurfaceBackground`, `PrimaryText`, `DefaultAccent`, …) read the active palette, so switching re-themes the app without a restart.
- Settings → Appearance offers Graphite (default) and Classic as two radio cards with a miniature of each. The choice is saved (`ui_theme` in `VoidPlayerAudioSettings`) and applied in `MainActivity` before the first frame.
- In Graphite, the background washes, accent glows and accent-tinted nav pill are off. The mini player and bottom bar are flat with hairlines, and dark album accents are lightened to 4.5:1. Classic keeps all of these exactly as before.
- Windows has no Classic switch yet: several of its pages still use literal colors rather than tokens, so a runtime switch would only re-color part of the window.
- Not yet checked on a device: the full-screen look of both themes, switching while music plays, and TalkBack reading the theme cards.
